# ТЗ на сборку файла Figma — МаркетШоп.by, ЛР№5

Что должно получиться по методичке: адаптивные макеты одной страницы веб-приложения
(6 разрешений), один экран мобильного приложения для 5 устройств и **интерактивный**
прототип для веба и мобильного. Ниже — структура файла, компоненты и карта переходов.

Все цвета берутся из `design/tokens.json`. Победившая палитра подставляется
переключением режима переменных — перекрашивать вручную ничего не нужно.

## 2. Переменные (Variables)

Создать **четыре коллекции**. Критично: цветовая коллекция с режимами — именно она
позволяет получить три варианта из одной разметки.

| Коллекция | Режимы | Содержимое |
|---|---|---|
| `color` | `A-light`, `A-dark`, `B-light`, `B-dark`, `C-light`, `C-dark` | 31 токен из `tokens.json` → `palettes.*` |
| `status` | — | 6 статусов описания × (bg, fg) — алиасы на `color` |
| `size` | — | spacing 0–96, radius, размеры тач-зон |
| `type` | — | 10 ступеней шкалы: размер, интерлиньяж, насыщенность |

**Имена переменных должны совпадать с ключами `tokens.json`** (`bg`, `surface`, `text`,
`text-muted`, `brand`, `accent`, `on-accent`, `accent-soft`, …). Тогда CSS-переменные
в `tokens.css` и переменные Figma называются одинаково, и разработчик фронтенда
не угадывает соответствие.

> После выбора палитры (этап 4) режимы `B-*` и `C-*` **не удалять** — они нужны
> как доказательство исследования в отчёте.

## 3. Компоненты — обязательные состояния

Каждый интерактивный компонент собирается как Component Set со свойством
`state` = `default / hover / focus / active / disabled / loading`.
Для веба обязательны все шесть, для мобильного — `default / pressed / disabled / loading`
(hover и focus на тач-устройствах не применяются).

### Базовые

| Компонент | Свойства (properties) |
|---|---|
| `Button` | `kind` = primary/secondary/ghost/danger; `size` = lg/md/sm; `icon` = none/left/right; `state` |
| `Input` | `state`; `filled` = true/false; `error` = true/false; `hint` = true/false |
| `Select` | `state`; `open` = true/false |
| `Checkbox`, `Radio`, `Switch` | `checked` = true/false; `state` |
| `Chip` | `kind` = filter/removable; `selected` = true/false |
| `Tabs` | `count` = 2/3/4; `active` = 1…4 |
| `Toast` | `kind` = success/warning/error/info |
| `Modal`, `BottomSheet` | `size` = sm/md/lg |
| `Skeleton` | `kind` = card/text/image |
| `EmptyState` | `kind` = search/cart/orders/queue |

### Предметные — ядро проекта

| Компонент | Свойства | Привязка |
|---|---|---|
| `ProductCard` | `cols` = 1/2/3/4; `badge` = none/belarus/fit; `discount` = true/false | лента и каталог |
| `Badge/Status` | `status` = incomplete/draft/pending_moderation/blocked/returned/published | ЛР№4 ENUM `description.status` |
| `Badge/Confidence` | `level` = low/medium/high | ЛР№4 ENUM `description.confidence`; **только в кабинетах**, не у покупателя |
| `DescriptionBlock` | `sostav`, `posadka`, `uhod`, `setka` = filled/empty | AC-02.2; `empty` → «Продавец не указал» |
| `SizeAssistant` | `state` = collapsed/params/result | US-03, US-04; overlay, не отдельный экран |
| `FitRating` | `value` = small/true/large | оценка посадки из отзывов, UC-09 |
| `AttributeCheck` | `missing` = 0/1/2/3+ | AC-06.2, поле `missing[]` из ответа API |
| `ModerationTaskRow` | `confidence`, `claimed` = true/false | UC-16, захват задачи |
| `AssistantPanel` | `state` = idle/thinking/confirm/error | UC-30, панель AI-ассистента |
| `ErrorBanner` | `code` = 400/401/403/404/409/413/422/429/503 | таблица 11 ЛР№4, формат RFC 9457 |

> `ErrorBanner` с девятью вариантами — не формальность: 401 встречается в **47** операциях
> API, это самое частое состояние системы, и его нельзя оставить непроектированным.

## 4. Сетки (Layout Grid) для страницы `Web — адаптив`

Страница для адаптации — **Каталог с фильтрами**. Значения из `tokens.json` → `grid.breakpoints`.

| Артборд | Контейнер | Колонок | Гаттер | Колонка | Поля | Карточек в ряд | Фильтры |
|---|---|---|---|---|---|---|---|
| 1440 | 1320 | 12 | 24 | 88 | 60 | 4 | сайдбар 3 колонки |
| 1024 | 984 | 12 | 24 | 60 | 20 | 3 | сайдбар 3 колонки |
| 768 | 720 | 8 | 24 | 69 | 24 | 3 | кнопка + drawer |
| 600 | 552 | 8 | 16 | 55 | 24 | 2 | кнопка + bottom sheet |
| 414 | stretch | 4 | 16 | — | 16 | 2 | липкая панель снизу |
| 360 | stretch | 4 | 16 | — | 16 | 2 | липкая панель снизу |

Для 414 и 360 тип сетки — **Stretch** (Count 4, Margin 16, Gutter 16), ширина колонки
считается автоматически.

Рядом с артбордами разместить **таблицу «что меняется на каждом брейкпоинте»** —
это содержательная часть задания, а не сами шесть картинок.

## 5. Страница `Mobile — устройства`

Экран — **главная после авторизации** (лента «Специально для вас»), как требует методичка.

| Устройство | Размер | Сетка | На что обратить внимание |
|---|---|---|---|
| iPhone SE (3rd) | 375 × 667 | 4 кол., поля 16 | минимальный кейс; проверка AC-02.1 — без горизонтальной прокрутки |
| iPhone 15 Pro | 393 × 852 | 4 кол., поля 16 | safe area сверху и снизу, Dynamic Island |
| Pixel 7 | 412 × 915 | 4 кол., шаг 8 dp | Material: системная кнопка «Назад», положение FAB |
| iPad mini | 744 × 1133 | 8 кол., поля 24 | 2 колонки карточек, нижняя навигация → side rail |
| iPad Pro 11″ | 834 × 1194 | 12 кол., поля 32 | master-detail: лента слева, превью карточки справа |

Тач-зоны: не меньше **44×44 pt** на iOS и **48×48 dp** на Android — требование ЛР№1 п. 2.3.

## 6. Интерактивный прототип

### 6.1. Техника Figma, которую нужно применить (и описать в отчёте)

| Приём | Где применить |
|---|---|
| **Overlays** | «Ассистент по размеру», drawer фильтров, модалка возврата карточки, вход при 401 |
| **Smart Animate** | переход из ленты в карточку, анимация добавления в корзину |
| **Interactive Components** | чекбоксы фильтров, переключатель темы, табы — без дублирования фреймов |
| **Variables + Conditional logic** | счётчик корзины, состояние «гость / авторизован», валидация пароля, лимит партии 20 позиций |
| **Scroll behavior** | `Fixed` — шапка и нижняя навигация; `Sticky` — панель покупки в карточке |
| **Scroll to / Overflow** | горизонтальные chips категорий на 360 px |
| **Device frames** | на страницах 05, 07 |
