## 0. Подготовка (один раз, ~30 мин)

1. **Слить PR** в `main` по порядку: сначала #24 (ЛР5, веб-прототип), потом #25 (ЛР6).
   Через 1–2 минуты всё откроется на сайте.
2. **Ссылки для сессий** (работают после слияния):

   | Что | Ссылка |
   |---|---|
   | Веб-прототип (старт) | https://fpmi-hci-2026.github.io/hci-10-project-group-1/lab5/mockups/web-login.html |
   | Мобильный прототип (старт) | https://fpmi-hci-2026.github.io/hci-10-project-group-1/lab5/mockups/prototype-login.html |
   | Экран сортировки — веб | https://fpmi-hci-2026.github.io/hci-10-project-group-1/lab6/materials/cardsort.html?p=web |
   | Экран сортировки — мобильное | https://fpmi-hci-2026.github.io/hci-10-project-group-1/lab6/materials/cardsort.html?p=mobile |
   | Протокол для печати | https://fpmi-hci-2026.github.io/hci-10-project-group-1/lab6/materials/protocol.html |

3. **Напечатать протокол** — 12 экземпляров (⌘P). Один протокол — один участник на одной платформе.
4. **Найти 12 участников**: 6 на веб и 6 на мобильное, по 2 из каждой группы ЛР№1:
   «осознанные покупательницы», «быстрые покупатели», «новички». Прототип они видеть
   не должны. Один человек проходит только одну платформу.
5. **Роли на сессии**: ведущий (читает задания, не подсказывает) и наблюдатель
   (секундомер, заполняет протокол).
6. **Устройства**: веб — ноутбук, окно браузера на весь экран; мобильное — смартфон
   участника или свой, ссылка открыта заранее.

## 1. Сессия с участником (~25 мин), всё по протоколу

| Шаг | Что делать | Что записать в протокол |
|---|---|---|
| 0 | Прочитать вступление из протокола | — |
| 1 | Карточная сортировка: открыть экран с номерами, задать Q1–Q8 | номер области, ✓ если совпал |
| 2 | Тест ожиданий: показать элементы E1–E8 в прототипе, спросить «что произойдёт / что это значит» | ответ кратко, ✓ если совпал по смыслу. E6 (отпечаток) — только на мобильном |
| 3 | Задания T1–T5 с секундомером, лимит 3 мин на задание | ✓/✗, время в секундах, число ошибок, заметки |
| 3a | Отдельно засечь T2→T5 подряд | контрольное время |
| 4 | Участник заполняет анкету SUS (страница 3 протокола) | 10 оценок 1–5 |

Правила: не подсказывать, не говорить «правильно / неправильно», не торопить.
Если участник застрял на 3 минуты — задание ✗, показать путь и перейти к следующему.
**Ошибка** — переход не туда, возврат назад, неверный выбор.

## 2. TreeJack (Optimal Workshop), ~40 мин на настройку

Нужно **два исследования**: веб и мобильное (деревья разные). Если бесплатный план не
даёт создать второе, создайте его после закрытия первого.

1. Войти на https://app.optimalworkshop.com → **Create study → Treejack (Tree test)**.
   Название: «МаркетШоп — веб» (второе — «МаркетШоп — мобильное»).
2. **Tree** → вставить дерево из `docs/lab6/materials/tree-web.txt` (второе — `tree-mobile.txt`).
   Уровни заданы табуляцией. Если вставка не распознала уровни, введите дерево вручную по файлу.
3. **Tasks** → добавить 6 заданий и в каждом отметить правильный узел:

   | № | Текст задания | Веб: правильный узел | Мобильное: правильный узел |
   |---|---|---|---|
   | J1 | Вы хотите вернуть платье, купленное неделю назад | Профиль › Возврат и обмен › Оформить возврат | так же |
   | J2 | Узнайте, сколько дней даётся на возврат товара | Справка › Возврат и обмен: правила и сроки | Профиль › Справка › Возврат и обмен: правила и сроки |
   | J3 | Найдите женские зимние сапоги | Каталог › Женское › Обувь › Сапоги | Главная › Каталог › Женское › Обувь › Сапоги |
   | J4 | Сохраните свои мерки, чтобы получать подходящие размеры | Профиль › Профиль и параметры размера › Мои мерки | так же |
   | J5 | Сравните две отложенные куртки | Избранное › Сравнение товаров | так же |
   | J6 | Найдите одежду белорусских производителей | Каталог › Сделано в Беларуси | Главная › Каталог › Сделано в Беларуси |

4. Включить **случайный порядок заданий** (Randomize tasks), язык интерфейса — русский, если есть.
5. **Launch** → разослать ссылку. Нужно **не меньше 6 прохождений на каждое дерево**
   (можно тем же участникам после сессии и любым знакомым из целевой аудитории).
6. После сбора: **Results → Analysis → Task results**. Для каждого задания выписать
   Success %, Directness %, Median time.
7. Для двух самых неудачных заданий сохранить скриншот **Pietree** (диаграмма путей).

## 3. Внести данные

Файлы в `docs/lab6/data/`. Первая строка — заголовок, его не трогать. Платформа: `web`
или `mobile`. 1 — да / успех, 0 — нет.

| Файл | Строка на… | Пример строки |
|---|---|---|
| `sessions.csv` | участник × задание T1–T5 (60 строк) | `P1,новичок,web,T3,1,74,1` — код, группа, платформа, задание, успех, время в с, ошибок |
| `sessions.csv` | контрольное время (12 строк) | `P1,новичок,web,CTRL,1,162,0` — задание `CTRL`, время T2→T5 подряд |
| `sus.csv` | участник (12 строк) | `P1,web,4,2,4,1,5,2,4,1,4,2` — оценки 1–10 по порядку |
| `cardsort.csv` | участник × вопрос (96 строк) | `P1,web,Q3,1` — 1 если номер совпал |
| `expectations.csv` | участник × элемент (90 строк) | `P1,web,E2,0` — 1 если ожидание совпало |
| `treejack.csv` | задание × платформа (12 строк) | `web,J2,67,50,24` — успех %, прямота %, медиана с |

Проще всего вносить в Google Таблицы и выгрузить «Файл → Скачать → CSV».

## 4. Обработать

```bash
cd docs/lab6
python3 metrics.py > results.md
```

Скрипт посчитает успех с 95 % доверительным интервалом, медиану времени, ошибки,
выполнение критерия «T5 за 3 минуты у 75 %», баллы SUS, попадания в сортировке,
совпадения ожиданий и сведёт TreeJack.
