## Введение

**Цель работы** — оценить интерактивные прототипы ЛР № 5 методами быстрой оценки концепций и юзабилити-тестирования и сформировать рекомендации по доработке интерфейса.

**Задачи:** зафиксировать задачи тестирования и численные критерии качества; провести обратную карточную сортировку, тестирование в TreeJack и тестирование ожиданий; оценить прототипы по контрольным спискам; проанализировать формы по моделям GOMS и TLM; измерить успех и время выполнения заданий и провести анкетирование SUS; сформулировать рекомендации.

Объект тестирования — прототипы мобильного (`lab5/mockups/prototype-login.html`) и веб-приложения (`lab5/mockups/web-login.html`). Каждый вид тестирования выполнен для обеих платформ.

## 1 Задачи тестирования и критерии качества

Задачи тестирования выведены из барьеров покупки, выявленных опросом ЛР № 1: несоответствие описания реальности (60,9 %), сложности с возвратом (39,1 %), невозможность примерить (28,3 %).

**Таблица 1 — Задачи тестирования и критерии**

| № | Задача тестирования | Метрика | Критерий |
|---|---|---|---|
| 1 | Пользователь проходит путь покупки без помощи | успех заданий T1–T5 | не менее 80 % по каждому заданию |
| 2 | Покупка выполняется быстро | время контрольного задания T5 | 75 % участников укладываются в 3 минуты |
| 3 | Ассистент по размеру находят и понимают | успех T3, тест ожиданий | не менее 80 % |
| 4 | Условия возврата видны до заказа | успех T4 | не менее 80 % |
| 5 | Структура разделов понятна | попадания в карточной сортировке и TreeJack | не менее 70 % по каждому вопросу |
| 6 | Интерфейс воспринимается удобным | SUS | не ниже 68 баллов |

Критерий 2 сформулирован по образцу методических указаний: контрольное задание выполняется в течение 3 минут 75 % участников.

## 3 Организация тестирования

Участники подбираются по профилям ЛР № 1: «Осознанные покупательницы», «Быстрые покупатели», «Новички», по два человека из каждой группы на платформу, всего 6 человек на платформу. Участники ранее не видели прототип. Методические указания называют достаточным для приложения средней сложности 4–8 человек.

Порядок сессии: обратная карточная сортировка → тестирование ожиданий → задания T1–T5 с фиксацией времени и ошибок → анкета SUS. Тестирование в TreeJack проводится удалённо отдельной ссылкой. Ведущий не подсказывает и не прерывает участника; разработчики присутствуют пассивно.

Результаты заносятся в файлы `data/sessions.csv`, `data/sus.csv`, `data/cardsort.csv`, `data/expectations.csv`. Показатели рассчитывает скрипт `metrics.py`: доля успеха с 95 % доверительным интервалом по скорректированному методу Вальда, медиана времени, баллы SUS.

## 8 Анализ форм веб-приложения по модели GOMS

Использована модель KLM-GOMS. Значения операторов по Card, Moran, Newell: K = 0,28 с (средний непрофессиональный наборщик), P = 1,10 с, B = 0,10 с (нажатие или отпускание кнопки мыши, щелчок — 2B), H = 0,40 с, M = 1,35 с, R — время ответа системы.

Проанализированы три формы, для каждой — два варианта и два способа ввода: «мышь» (переход между полями щелчком) и «клавиатура и мышь» (переход по Tab, подтверждение Enter). Итого 12 моделей. Модели записаны в `models.py`, время рассчитано скриптом.

Данные для расчёта: почта из 21 символа, пароль из 10, телефон из 9 цифр без кода страны, код из SMS — 4 цифры, время доставки SMS принято равным 5 с. В ассистенте вводятся рост «168» и обхват «96». При оформлении заказа меняются пункт выдачи (на два пункта вниз по списку) и способ оплаты (на два пункта вниз).

Варианты B: вход по номеру телефона и коду из SMS; ассистент с выбором роста и обхвата из выпадающих списков; оформление заказа мастером из трёх шагов «Получение → Оплата → Подтверждение».

**Таблица 10 — Модели GOMS для форм веб-приложения**

| Форма | Вариант | Ввод | Операторы | Время, с |
|---|---|---|---|---|
| Вход | A: почта и пароль | мышь | 3M + 3P + 6B + 4H + 31K | 18,23 |
| Вход | A: почта и пароль | клавиатура и мышь | 3M + P + 2B + H + 33K | 14,99 |
| Вход | B: телефон и код из SMS | мышь | 3M + 3P + 6B + 3H + 13K + R | 17,79 |
| Вход | B: телефон и код из SMS | клавиатура и мышь | 3M + P + 2B + H + 14K + R | 14,67 |
| Ассистент по размеру | A: ввод роста и обхвата | мышь | 5M + 5P + 10B + 4H + 5K | 16,25 |
| Ассистент по размеру | A: ввод роста и обхвата | клавиатура и мышь | 3M + P + 2B + H + 9K | 8,27 |
| Ассистент по размеру | B: выбор из списков | мышь | 6M + 6P + 12B | 15,90 |
| Ассистент по размеру | B: выбор из списков | клавиатура и мышь | 4M + P + 2B + 13K | 10,34 |
| Оформление заказа | A: одна страница | мышь | 4M + 4P + 8B | 10,60 |
| Оформление заказа | A: одна страница | клавиатура и мышь | 4M + P + 2B + 7K | 8,66 |
| Оформление заказа | B: мастер из трёх шагов | мышь | 6M + 6P + 12B + 2R | 16,50 |
| Оформление заказа | B: мастер из трёх шагов | клавиатура и мышь | 4M + P + 2B + 9K + 2R | 9,82 |

**Выводы.**

1. **Вход.** Варианты почти равны. Вариант B быстрее только при доставке SMS быстрее 5,4 с (мышь) или 5,3 с (клавиатура), а это время не зависит от интерфейса. Сохраняется вариант A. Его основной резерв — автозаполнение браузера и «Запомнить меня», которые убирают 31 нажатие K.
2. **Ассистент по размеру.** При вводе с клавиатуры вариант A на 2,1 с быстрее варианта B; при вводе мышью он медленнее всего на 0,35 с. Сохраняется вариант A. Автоматический перевод фокуса в первое поле уже заложен в прототип и экономит P + 2B = 1,3 с.
3. **Оформление заказа.** Одна страница быстрее мастера на 5,9 с мышью и на 1,2 с с клавиатуры, поскольку не требует подтверждения каждого шага. Сохраняется вариант A.
4. Во всех формах ввод с клавиатуры быстрее ввода только мышью — на 1,9–8,0 с. Поддержка Tab, Enter и видимого фокуса обязательна, что согласуется с требованием ЛР № 3 к навигации с клавиатуры.

## 9 Анализ форм мобильного приложения по модели TLM

Для сенсорного интерфейса использована модель TLM: KLM, расширенная операторами касаний. Значения операторов: T = 0,08 с — касание цели из исходного положения, S = 0,07 с — короткий свайп (El Batran, Dunlop); K = 0,28 с — касание клавиши экранной клавиатуры; M = 1,35 с; R — ответ системы: 0,3 с на открытие панели, 0,5 с на переход экрана, 1 с на проверку отпечатка. Переход к следующему полю выполняется клавишей «Далее» экранной клавиатуры (T).

**Таблица 11 — Модели TLM для форм мобильного приложения**

| Форма | Вариант | Операторы | Время, с |
|---|---|---|---|
| Вход | A: почта и пароль | 2M + 3T + 31K + R | 12,12 |
| Вход | B: отпечаток пальца | M + T + R | 2,43 |
| Ассистент по размеру | нижняя панель | 3M + 5T + R + 5K | 6,15 |
| Оформление заказа | корзина и оплата | 3M + S + 2T + R | 4,78 |

**Выводы.**

1. Вход по отпечатку в 5 раз быстрее ввода пароля, поэтому после первой авторизации он должен предлагаться по умолчанию.
2. Оформление заказа на мобильной платформе быстрее, чем в вебе (4,78 с против 8,66–10,60 с): получатель и пункт выдачи берутся из профиля, а кнопка находится в зоне большого пальца.
3. В ассистенте 4,05 с из 6,15 с приходятся на операторы M. Время можно сократить, если подставлять сохранённые в профиле мерки: тогда ввод не нужен и модель сводится к M + 2T + R.

## Заключение

1. Сформулированы шесть задач тестирования с численными критериями и пять тестовых заданий по пользовательским сценариям; T5 — контрольное задание с критерием «3 минуты у 75 % участников».
2. Подготовлены материалы обратной карточной сортировки (8 вопросов, 2 экрана), дерево и 6 заданий TreeJack, 8 элементов для тестирования ожиданий, протокол сессии и скрипт обработки результатов.
3. По контрольным спискам веб-прототип выполняет 9 пунктов из 16, мобильный — 8 из 14. Главная проблема обеих платформ — выбранный размер не сохраняется между шагами покупки.
4. По модели GOMS построено 12 моделей. Для всех трёх веб-форм сохраняются варианты A, ввод с клавиатуры быстрее ввода мышью на 1,9–8,0 с.
5. По модели TLM проанализированы три мобильные формы. Вход по отпечатку в 5 раз быстрее ввода пароля, подстановка сохранённых мерок сокращает работу с ассистентом с 6,15 с до 1,81 с.
6. Сформулированы 8 рекомендаций по модификации интерфейса; две из них — с высоким приоритетом.
