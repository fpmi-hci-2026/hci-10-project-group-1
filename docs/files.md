Код размещён в трёх репозиториях, подключённых к основному как подмодули: `backend/`, `frontend/`, `mobile/`.
Каждый ограниченный контекст предметной области — отдельный сервис серверной части. Сейчас реализованы
аутентификация, каталог, корзина и заказы; остальные контексты из [диаграммы компонентов](lab3/README.md#48-диаграмма-компонентов)
добавляются следующими сервисами по тому же образцу.

---

## 1. Серверная часть

```
backend/
├── libs/common/                    общая библиотека сервисов
│   ├── Security.kt                 проверка JWT, роли, публичные пути
│   ├── Errors.kt                   ошибки problem+json (RFC 9457) с машиночитаемым кодом
│   ├── Events.kt                   темы Kafka, CloudEvents, публикация после фиксации транзакции
│   ├── Page.kt                     постраничная выдача
│   └── Http.kt                     клиент внутренних запросов между сервисами
├── services/                       сервисы на Kotlin и Spring Boot
│   ├── gateway/                    шлюз: маршруты, ограничение частоты, CORS, Swagger UI
│   ├── auth/                       регистрация, вход, токены
│   ├── catalog/                    товары, атрибуты, остатки, фото, поиск, загрузка CSV
│   └── orders/                     избранное, корзина, заказы, оплата, статусы доставки
├── scripts/e2e.py                  сквозной сценарий через шлюз
├── deploy/Caddyfile                HTTPS для облачного развёртывания
├── docker-compose.yml              сервисы и инфраструктура
├── Dockerfile                      многоэтапная сборка сервисов на Kotlin
└── .github/workflows/ci.yml        detekt, тесты, SonarCloud, образы
```

Сервис на Kotlin устроен одинаково: `src/main/kotlin` — приложение, контроллеры, логика и подписчики событий,
`src/main/resources/db/migration` — миграции Flyway своей схемы, `src/test` — тесты JUnit (интеграционные — с
PostgreSQL в Testcontainers). Сервисы небольшие, поэтому слои разделены файлами, а не пакетами.

| Правило | Как соблюдается |
|---------|-----------------|
| У сервиса своя схема данных | Отдельная схема PostgreSQL на сервис, чужие таблицы не читаются |
| Сервисы связаны событиями | Изменения состояния публикуются в Kafka; синхронно — только внутренние запросы через `/internal` |
| Внутренние запросы не выходят наружу | Шлюз не маршрутизирует пути `/internal` |

## 2. Веб-приложение

```
frontend/
├── src/
│   ├── api/                        клиент API, сессия и обновление токена, загрузка данных, типы
│   ├── components/                 шапка, карточка товара, общие элементы
│   ├── pages/buyer/Home.tsx        главная: категории, фильтр «Сделано в Беларуси», сортировка, товары
│   ├── styles/                     токены цвета, шрифты, тёмная тема
│   └── App.tsx                     маршруты
├── tests/                          тесты Vitest и Testing Library
├── Dockerfile, nginx.conf          образ со статикой и прокси API
└── vercel.json                     публикация на Vercel
```

## 3. Мобильное приложение

```
mobile/app/src/
├── main/kotlin/by/marketshop/app/
│   ├── data/                       клиент API, модели, сессия, формат цен
│   ├── ui/
│   │   ├── App.kt                  каркас экрана
│   │   ├── Components.kt           карточка товара, загрузка данных, сообщения
│   │   ├── theme/                  токены цвета, светлая и тёмная тема
│   │   └── screens/Home.kt         главная: подборки и товары из каталога
│   └── MainActivity.kt
└── test/                           тесты клиента API, форматов и подборок
```
